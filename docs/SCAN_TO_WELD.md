# Сканирование детали → положение в MoveIt → сварочный проход

**Текущий режим веб-панели:** используется положение детали в MoveIt/RViz.
Сканер продолжает обновлять облако и модель отдельно, но панель не проверяет
наличие/возраст скана, файл калибровки или подтверждение совмещения перед запуском.
Из сведений о скане показано только время последнего обновления облака в RViz.
Сохраняются проверки робота, столкновений и неизменности сцены при выполнении.

Объединены соседний `kVantron-Weld-Windows` и ROS-проект JAKA.
Сканирование/реконструкция и CAD остаются в Windows-приложении. Оно передаёт
измеренное облако в стабильной системе камер, исходную сетку CAD и начальное
приближение её позы. Уточнение положения и всё управление роботом выполняются
на стороне ROS/MoveIt. Один скан — одна известная CAD-деталь.

## Выбор шва на детали в веб-интерфейсе

Откройте `http://localhost:8090` (панель `./run_scan_welding.sh`). В блоке
«Швы детали» показаны внешний контур верхней поверхности, продольная прорезь
и круглое отверстие. Нажмите нужную карточку или линию контура на модели:
выбранный шов подсветится, его имя и длина появятся под изображением.
«Деталь крупно» приближает заготовку для выбора небольших контуров.
Фильтр «Все поверхности» открывает также нижние и боковые контуры.

Для сварки только части контура задайте «Начало» и «Конец» в процентах.
Отдельный прямой участок можно выбрать в режиме «Одно ребро».
В планировщик передаётся ID выбранного контура/ребра; отверстия не соединяются
с внешней границей дополнительными перемычками. Отверстия на изображении CAD
сохраняются прозрачными. При отсутствии MoveIt можно выбрать шов на сохранённой
CAD, но построение маршрута и выполнение требуют подключённой сцены.

После проверки положения детали в RViz: «Предпросмотр» →
«Построить план» → проверка маршрута → отдельный запуск сварки.
Сам выбор шва не запускает движение и не заменяет заготовку в сцене.
Если панель была открыта во время обновления, обновите страницу через Ctrl+F5.

## Что сделано

- Добавлен read-only endpoint сканера `/api/spectrum/moveit-export`.
- Принимается только новый захват активного задания с метрической калибровкой
  и восстанавливаемой стабильной системой камер; тестовое облако не подходит.
- Преобразование камеры в `world` привязано к подписи измерительной системы.
  Изменение масштаба, калибровки или порядка камер требует новой привязки.
- Выполняется локальное шестикоординатное совмещение CAD с измеренными точками:
  перенос до 50 мм и поворот до 15° от начального приближения. Неопределимые
  направления, недостаточное перекрытие, RMSE/P95 более 2 мм отклоняются.
- Точки известной горизонтальной поверхности стола исключаются из сравнения;
  сам стол остаётся collision-объектом. Геометрия детали не должна проникать
  под стол более чем на 1 мм или выходить за его границы.
- Облако показывается голубым в RViz, принятая CAD-деталь — оранжевым.
- После обнаружения оператор применяет результат. Передача модели не двигает
  физическую деталь и не запускает робота. После неё выбирается грань/ребро,
  строится новый план и отдельно запускается исполнение.
- В объединённом режиме подготовка/исполнение прямого цикла JAKA в приложении
  сканера блокируются; управление принадлежит существующему ROS SDK-драйверу.

## Подготовка и запуск

Соседний комплект уже обновлён установщиком интеграции. При переносе Windows-
приложения в другую папку установите мост в **его фактическую рабочую копию**:

```bash
cd ~/welding/JakaZu12
python3 integrations/install_kvantron_bridge.py \
  ../kVantron-Weld-Windows/kVantron-Weld-Windows
# Для копии на диске Windows укажите, например, /mnt/c/kVantron-Weld.
./setup_rangevision.sh
./build.sh --real
```

В Windows установите зависимости сканера его `01-Setup.cmd`, настройте камеры,
проектор и примите измерительную калибровку по инструкции соседнего проекта.
Запускайте **`04-Scan-For-MoveIt.cmd`**, а не старый самостоятельный цикл робота.
Если приложение уже было запущено другим способом, остановите его и запустите
заново этим файлом. Запуск старого процесса не переключает его режим.

В отдельном терминале WSL запустите JAKA:

```bash
./run_real.sh 10.5.5.100
```

Затем объединённую панель:

```bash
./run_scan_welding.sh
```

Адрес панели робота: **http://localhost:8090**. Адрес сканера:
**http://127.0.0.1:8158** в браузере Windows.

По умолчанию используется `windows-local`: WSL запускает локальный PowerShell,
который читает только endpoint экспорта через Windows loopback. Поэтому сервер
сканера не нужно открывать на `0.0.0.0`, менять firewall или передавать USB в WSL.
Мост не отправляет аппаратных команд приложению сканера. Для сканера в том же
Linux-окружении можно явно передать `--scanner-url http://127.0.0.1:8158`.

## Дополнительный CLI: измерительная привязка камеры

Этот раздел описывает отдельный измерительный CLI, а не проверки веб-панели.

Калибровка стереокамер и положение стола в браузере сами по себе не определяют
систему координат робота. Для переноса требуется независимо проверенное
преобразование **стабильная система камер → robot world**.

1. В сканере создайте задание с фактическим CAD, выполните реальный скан.
2. Получите `frame_signature` командой `scan_job.py info` через Python окружения
   `.venv-rangevision`, передав `--scanner-url windows-local`, `--calibration
   scans/calibration.json` и `--report scans/detection.json`.
3. Измерьте соответствующие неподвижные реперы в этой системе камер и в
   `world` робота. Координаты реперов в системе камер — после восстановления
   исходной системы реконструкции, не после произвольного перемещения облака
   в браузере. Endpoint содержит именно такие `camera_points_mm`.
4. Создайте `scans/landmarks.json`: `scanner_mm`, `world_m` (минимум 4 пары),
   а также **отдельные** `check_scanner_mm`, `check_world_m` (минимум 4 пары).
   Реперы должны быть разнесены по рабочему объёму; прямой/малой группы недостаточно.
5. Рассчитайте и независимо проверьте калибровку:

```bash
./run_rangevision.sh calibrate --landmarks scans/landmarks.json \
  --frame-signature СКОПИРОВАННАЯ_ПОДПИСЬ --output scans/calibration.json
```

Допуск контрольных точек — 1 мм. Это порог допуска к дальнейшим испытаниям,
не гарантия необходимой для конкретной сварки точности. Не копируйте единичную
матрицу из тестов и не принимайте визуальное совпадение за измерение.
Измеренный TCP горелки, её монтаж, нагрузка и система базы должны соответствовать
настройкам реального робота. После перестановки сканера выполните привязку заново.

## Рабочая последовательность

1. Запустите `run_real.sh` и `run_scan_welding.sh`.
2. Проверьте положение и ориентацию детали в RViz. Панель использует эту геометрию.
3. Выберите шов на модели или в списке «Швы детали», при необходимости задайте участок.
4. Выполните предпросмотр, постройте и проверьте маршрут, затем отдельно запустите сварку.
5. После прохода TCP поднимается на 25 см с сохранением ориентации.

Веб-панель передаёт `--use-scene-workpiece` и не вызывает команды сканера.
Изменение модели или стола после планирования по-прежнему требует нового плана.
Время облака выводится из `scans/scan_status.json` (или сохранённого кэша) и служит
только справкой; отсутствие или давность скана не блокируют выполнение.

Запись TCP остаётся доступной отдельно через `scan_job.py tcp`; кнопки записи,
импорта и подтверждения скана из веб-интерфейса убраны. Дополнительный CLI с
`--scan-report` сохраняет собственные проверки измерений и срока подтверждения,
но при запуске из веб-панели этот режим не используется.

## Ограничения и проверка

Это локальное уточнение положения **известной** детали, а не глобальный поиск
произвольных предметов. Вне диапазона 50 мм/15° необходимо улучшить начальное
приближение. Симметрии CAD могут допускать несколько одинаковых совпадений;
проверяйте ориентацию по реперам/асимметричным признакам. Одной плоскости сверху
недостаточно для полной позы. Нужны независимые измеренные поверхности.

Mesh ограничен 20 000 треугольников и миллионом точек выборки: сложный CAD нужно
упростить до подходящей collision-модели, сохранив важную геометрию прохода.
Переход от CAD к плоским граням/рёбрам использует существующий модуль заготовок;
обработка произвольных криволинейных CAD-швов в эту интеграцию не входит.

Облако — визуальное измерение, а не автоматически созданный OctoMap. Неизвестные
зажимы, стойка сканера и кабели должны быть добавлены в collision-сцену отдельно.
Оба приложения должны быть без активных движений во время сканирования/применения.
Это программные проверки, не аппаратная блокировка одновременных клиентов.
Управление сварочной дугой/источником не добавлялось: кнопка запуска исполняет
траекторию существующим драйвером; автоматический поджиг требует отдельной
настроенной интеграции с конкретным источником.

Проверка без оборудования:

```bash
source setup_isaac.bash
.venv-rangevision/bin/python -m pytest src/ur10_isaac_moveit_config/test/test_scan_pose.py -q
.venv-rangevision/bin/python src/ur10_isaac_moveit_config/test/scan_job_integration.py
```

Последний тест использует искусственный HTTP-сканер, сцену и неподвижную обратную
связь только в ROS-домене 184 с loopback discovery. Проверяет обнаружение 6D-позы,
отдельное применение CAD и блокировку изменённого скана. SDK-драйвер не запускает.
Работа с физическим Spectrum и точность на столе требуют испытаний после установки
Windows-зависимостей и измеренной калибровки; эти испытания пока не проведены.

# Координатная сетка стола в RViz

При запуске JAKA через `run_real.sh` или `run_sim.sh` публикуется слой
`Table grid A1-X16` (`/table/grid`, visualization_msgs/MarkerArray).
Сетка перенесена из соседнего проекта `adaptive_weld/workspace.py`:
1200 × 800 мм, шаг 50 мм, 24 столбца A–X и 16 рядов 1–16,
диаметр отверстий приблизительно 15 мм, первые центры в 25 мм от краёв.
В соседнем проекте отступы помечены как неизмеренные; эта пометка сохранена.
Адрес обозначает центр отверстия, начало системы стола находится на краю,
а не в A1. Координаты A1 в системе стола: (25, 25, 0) мм.

Система `table_grid`: X вдоль букв, Y вдоль номеров рядов, Z вверх.
Текущий поворот к world равен −90°, начало в world: (−440, 135, 0) мм.
Это соответствует существующему положению столешницы:
world X от −440 до 360 мм, world Y от −1065 до 135 мм, верх Z=0.
По наблюдению оператора «в реальности O8, в модели O9» стол и сетка
сдвинуты на +50 мм по world X: O8 теперь занимает прежнее положение O9.
Это ручная поправка смещения по одному ориентиру, не полная калибровка.
Для ориентации:

| Адрес | X/Y стола, мм | X/Y/Z world, мм |
|---|---|---|
| A1 | 25 / 25 | −415 / 110 / 0 |
| R3 | 875 / 125 | −315 / −740 / 0 |
| O8 | 725 / 375 | −65 / −590 / 0 |
| X16 | 1175 / 775 | 335 / −1040 / 0 |

Настройки лежат в `src/jaka_zu12_moveit_config/config/table_grid.json`,
координаты всех 384 отверстий — в соседнем `table_grid_coordinates.csv`.
Слой визуальный: поверхность стола остаётся прежним препятствием `floor`,
сетка не становится объектом сварки. Разметка не калибрует камеру и сама
по себе не подтверждает физическую точность привязки к роботу.
При запуске реального робота и симуляции добавляются стол и сохранённая CAD-модель
детали 88 × 40 × 5 мм с прорезями. Куб больше не добавляется. Модель оранжевая,
стол серый. Геометрия и последняя найденная поза хранятся в
`src/jaka_zu12_moveit_config/config/workpiece_model.json`.

При `run_real.sh` после каждого нового готового облака автоматически определяется
положение и ориентация этой модели: выделяется связная плоская поверхность детали,
сравниваются направления и совпадение CAD с измеренными точками. Цилиндр и удалённые
посторонние предметы не используются как поверхность заготовки. Масштаб CAD не меняется.
Поддерживаются тонкие детали с толщиной вдоль локальной Z. При несовпадении размеров,
недостаточном покрытии или плохом совмещении прежняя модель остаётся на месте.
Обновление сцены разрешено только при неподвижном роботе и неизменных препятствиях.
Подтверждённая через отдельное `detect/apply` модель автоматически не перезаписывается.

Статус: `/scanner/workpiece_status`, отчёт: `scans/auto_workpiece.json`.
Автоматическое совпадение в текущем режиме — **предварительное**: камера пока привязана
к роботу вручную для просмотра. Модель помечена типом `scanner_preview_unregistered`.
Веб-панель использует её текущую геометрию в режиме `--use-scene-workpiece`,
ориентируясь на просмотр в RViz, без отдельного подтверждения скана. Полное совпадение
нижней и скрытых поверхностей одним видом сверху не подтверждается.
`./run_scan_preview.sh --view-only` только показывает облако и не меняет сцену.

Для обновления стартового CAD из выбранного Windows-проекта используйте Windows Python
сканера с `integrations/export_startup_model.py SCANNER_ROOT OUTPUT_JSON`.

Оператор указал зону сканирования O1–T10. Её граница показана голубым контуром:
X стола 725…975 мм, Y стола 25…475 мм (250 × 450 мм между центрами отверстий).
В world это X −415…35 мм, Y −840…−590 мм; центр (−190, −715, 0) мм.
Эта граница описывает область съёмки, а не ограничивающий прямоугольник самой детали.

Для уже открытого RViz: Add → By topic → /table/grid → MarkerArray.
В свойствах слоя можно отдельно скрывать `hole_addresses` (подписи),
`hole_rings` (отверстия), `grid_lines` (линии) и `table_axes` (оси).
Отдельный запуск публикации: `ros2 run jaka_zu12_moveit_config table_grid.py`.

# Просмотр облака без привязки к роботу

При запуске `./run_real.sh 10.5.5.100` просмотр облака запускается автоматически
и завершается вместе с ROS launch. Для отключения передайте
`./run_real.sh 10.5.5.100 0.5 scan_preview:=false`.
Если служба Windows на порту 8158 выключена, запуск поднимает её скрытым
процессом через `integrations/ensure_scanner.ps1`. Уже работающая служба и
текущая съёмка не перезапускаются. Журналы службы:
`%LOCALAPPDATA%/WeldingStation/logs/scanner-service*.log`.
При единственном независимом внешнем экране проектор выбирается автоматически;
основной или зеркальный экран не используется. Для нескольких внешних экранов
нужно явно указать внутренний ID адаптера в `config.cmd`:
`set "SPECTRUM_PROJECTOR_DISPLAY=3"`. Имя Windows DISPLAY2 может соответствовать
внутреннему ID 3; номера этих двух систем не следует смешивать.

Для отдельного запуска используйте `./run_scan_preview.sh`. Скрипт автоматически
снимает одиночные серии одну за другой без поворота платформы. После восстановления
новое облако публикуется в `/scanner/preview_points`. Это последовательные сканы,
а не видеопоток глубины: деталь должна быть неподвижна в течение серии из 41 рисунка.
Состояние проверяется каждые 5 секунд; полная съёмка и восстановление занимают дольше.
Для чтения готовых сканов без запуска камер: `./run_scan_preview.sh --view-only`.
Отмена текущей серии в панели сканера приостанавливает автоматическую съёмку до
перезапуска просмотра. После трёх неудачных серий автоматический захват также
приостанавливается. Сохраняется ограничение сканера в 200 серий на одно задание.
Перед совмещением CAD, подтверждением положения и сваркой остановите автоматическую
съёмку: новый захват отменяет актуальность предыдущего совмещения.
Диагностика доступна в `/scanner/preview_status` (std_msgs/String, JSON).
В конфигурации MoveIt RViz включён оранжевый слой
`Scanner preview - UNCALIBRATED`. В уже открытом RViz его можно добавить
через Add → By topic → /scanner/preview_points → PointCloud2.

Для отдельного окна просмотра после `source ./setup_isaac.bash`:
`rviz2 -d src/jaka_zu12_moveit_config/config/scan_preview.rviz`.

Это только просмотр: начало координат выбирается по первому облаку и сохраняется
в `scans/preview-anchor.json`. Оно условно размещается в центре зоны O1–T10:
world (−0.190, −0.715, 0) м. Последующие сканы используют то же начало координат, поэтому
смещение детали остаётся видимым. Для просмотра камера направлена вдоль возрастающих
рядов 1→10, исходная оценка наклона вниз — 30°. Видимая опорная плоскость первого
подходящего скана выравнивается горизонтально жёстким поворотом без изменения размеров
и толщины детали. Поворот сохраняется в `scans/preview-orientation.json` и повторно
не рассчитывается на каждом новом скане. Для явного обновления опорной плоскости
используйте `./run_scan_preview.sh --relevel` при неподвижной плоской опоре в кадре.
Это визуальная подстройка по доминирующей поверхности, не доказательство того,
что эта поверхность является столом. Положение и
ориентация относительно робота не измерены. Параметр `--center X Y Z`
меняет только размещение для просмотра. Этот слой не добавляет препятствий
в MoveIt и не разрешает сварку. Для совмещения с роботом требуется отдельная
измеренная привязка; режим просмотра не создаёт calibration.json.
Размер облака не растягивается до размеров зоны: точки детали не описывают всю
область проектора. По двум адресам углов нельзя определить поворот камеры,
положение каждой точки внутри зоны и абсолютную высоту. Центрирование является
лишь предварительным размещением, а не точным отображением физических координат.

Если подставку убрали и деталь теперь лежит на столе, высотный ориентир можно
переустановить один раз по готовому скану:
`./run_scan_preview.sh --view-only --rebase-table`.
Для этой команды сначала остановите уже работающую публикацию облака.
Нижняя устойчивая граница облака (2-й процентиль, с исключением редких нижних
выбросов) помещается на высоту стола. Меняется только вертикальный перенос;
XY, сохранённый поворот, масштаб, толщина и исходные точки сохраняются.
Предыдущий ориентир архивируется в `scans/preview-anchor.before-height-*.json`.
Поправка хранится в `scans/preview-anchor.json` и используется при обычном запуске.
На последующих сканах высота автоматически не обнуляется. Это визуальная оценка
при условии видимой нижней границы детали, а не измеренная привязка камеры.
