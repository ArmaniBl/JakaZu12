## Запуск

1. Остановите прежний ROS launch и симуляцию.
2. В Isaac откройте `C:\Users\user\Desktop\ur10\ur_welding_torch.usda`.
3. Включите Play.
4. В WSL выполните:

```bash
cd ~/jaka_zu12_welding
./build.sh
./run_sim.sh
```

В RViz появятся робот, горелка и тестовая заготовка. Планирование учитывает
collision-геометрию инструмента. Если менялась геометрия заготовки, синхронизируйте
её отображение в Isaac отдельно, как и раньше.

Для модуля сварки используйте новый профиль TCP:

```bash
# Отдельный терминал, предпросмотр / план без движения.
./weld.sh --face z_plus
./weld.sh --face z_plus --mode plan

# Панель с TCP горелки.
./run_web.sh --port 8090
```

Насадка включена по умолчанию в стандартные модели MoveIt для UR10 и JAKA.
`run_sim.sh` запускает ROS/MoveIt/RViz для подключения к уже работающему Isaac;
сам Isaac Sim этот скрипт не запускает. Дополнительные скрипты запуска насадки не нужны.

Для физического JAKA:

```bash
./build.sh --real
./run_real.sh <IP_КОНТРОЛЛЕРА>
# Другой терминал:
./run_web.sh --robot jaka_real --port 8090
# Либо CLI:
./weld.sh --robot jaka_real --mode plan
```

В модели JAKA монтажный фрейм совмещён с `Link_6`, а группа `jaka_zu12`
продолжена до `welding_tcp`. Фактическое положение адаптера и TCP на физическом
роботе необходимо измерить: здесь принята установка MountFrame без дополнительного
смещения/поворота относительно фланца. Это геометрическая конфигурация, не калибровка.
После изменения модели перезапустите существующий launch и панель: уже работающий
`move_group` не перечитывает изменённый URDF автоматически.

Исполнение полного сварочного маршрута с новой насадкой отдельно не проверено:
её размеры и смещение TCP меняют досягаемость и коллизии прежних траекторий.

## Крепление и TCP

USD-путь: `/World/ur10/wrist_3_link/WeldingTorch`.
`MountFrame` модели совмещён с `tool0`/фланцем, жёстко следует за `wrist_3_link`.
В данной модели UR10 суммарный фиксированный поворот `wrist_3 → flange → tool0`
равен единичному. Дополнительные rigid body и шарниры не добавляются:
коллизии инструмента принадлежат существующему rigid body запястья.
Исходное положение `LowerPivot` сохранено; регулировка его угла требует повторного экспорта.

В URDF добавлены `welding_torch_link` и фиксированный `welding_tcp`.
Рабочий TCP находится в центре переднего торца `CopperContactTip`. Его положение вычисляется по геометрии относительно `NozzleTip`, а ориентация сохраняется вдоль оси сопла. В USD это отдельный фрейм `WeldingTCP`; в ROS — `welding_tcp`:

| Параметр | Значение |
| --- | --- |
| XYZ, м | −0,018; 0,229114062985; 0,101956156188 |
| RPY, рад | 2,44346105075; 0,000000097058; −3,14159253792 |

Ось +Z направлена наружу вдоль конца горелки. Контактный наконечник выступает
примерно на 1 мм за край сопла. Старый CAD-фрейм `LowerPivot/Frames/TCP`
сохраняется в исходном файле, но не используется для рабочего движения:
он находился на 10 мм впереди сопла, примерно на 9 мм впереди физического конца.
Параметр `--offset` теперь отсчитывается от физического конца горелки.
По умолчанию он по-прежнему равен 30 мм; смена TCP не означает автоматическое
касание детали или изменение сварочного зазора. Измерение физического TCP JAKA
остаётся отдельной процедурой калибровки.

## Геометрия и коллизии

Визуальная геометрия экспортирована в STL по 11 группам материалов с сохранением
цветов (122 908 треугольников). Текстуры и сложные USD-шейдеры не переносятся.
Для MoveIt использована штатная упрощённая collision-геометрия CAD (1484 треугольника).
В исходном файле все 26 collision-мешей были выключены: в новом USD они включены,
для динамического rigid body задано `convexHull` на каждом компоненте.
MoveIt использует треугольную поверхность этих же компонентов; точная форма
контактов PhysX/FCL может различаться из-за convex hull и допусков движков.

У гибкого шланга штатных коллизий не было. Для него добавлена одинаковая
консервативная прямоугольная оболочка в USD и URDF с запасом 1 мм с каждой стороны.
Она проверяется как неподвижная часть инструмента, деформация шланга не моделируется.
Отключена только пара `wrist_3_link` ↔ `welding_torch_link`, соответствующая
монтажному контакту. Коллизии инструмента с остальными звеньями и миром сохраняются.
Масса и инерция инструмента не калиброваны: новые данные нагрузки не задавались.

## Повторный экспорт

Источник сохранён в `src/ur10_isaac_moveit_config/assets/`, готовые STL — в `meshes/torch/`.
Для штатного ROS-запуска `usd-core` не требуется. Для повторного экспорта создайте
отдельное окружение Python с `usd-core` и `numpy`, затем:

```bash
diagnostics/usd_env/bin/python isaac/attach_torch.py \
  --source /mnt/c/Users/user/Desktop/ur10/JTM_RevC_MB_EVO36_0140528.usd \
  --scene /mnt/c/Users/user/Desktop/ur10/ur_welding.usd \
  --output /mnt/c/Users/user/Desktop/ur10/ur_welding_torch_new.usda

diagnostics/usd_env/bin/python isaac/check_torch.py \
  /mnt/c/Users/user/Desktop/ur10/ur_welding_torch_new.usda
```

Выходной файл должен быть новым: существующая сцена не перезаписывается.
Экспорт обновляет STL и `welding_torch.xacro`; после него пересоберите пакет.
