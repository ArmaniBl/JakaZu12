# Отчёт № 1. Настройка среды и интеграция Isaac Sim с ROS 2

**Дата:** 5 ноября 2026 года.  
**Этап:** подготовка рабочего пространства и канала управления UR10.

## Цель

Подготовить папку проекта к работе с Isaac Sim на Windows 11 и ROS в WSL2 Ubuntu 24.04,
используя исходный репозиторий конфигурации JAKA ZU12. Найти и отключить лишние
ROS-топики, организовать управление роботом UR10 и добавить тестовую заготовку.

## Исходные условия

Рабочая папка была пустой. Исходный репозиторий был рассчитан на ROS 2 Humble
и Ubuntu 22.04, тогда как в WSL был установлен ROS 2 Jazzy. На Windows обнаружен
Isaac Sim `6.0.0-rc.22`.

Симулятор предоставлял интерфейс `sensor_msgs/msg/JointState`:

| Топик | Назначение |
| --- | --- |
| `/joint_states` | Передача фактических состояний суставов из Isaac в ROS |
| `/joint_command` | Приём суставных команд симулятором |

Кроме этого, в ROS-графе присутствовали `/goal_pose` и `/joint_commands`,
не требовавшиеся для выбранной схемы управления.

## Выполненные работы

### Репозиторий и окружение

Репозиторий `ArmaniBl/JakaZu12` загружен непосредственно в рабочую папку,
создана локальная ветка `welding`.

Добавлен пакет `ur10_isaac_moveit_config`, адаптированы зависимости и сборка
для Jazzy. `build.sh` собирает пакет симуляции UR10; исходники конфигурации
и SDK JAKA сохранены в репозитории, но в запуске Isaac не участвуют.

Добавлены или изменены основные команды:

| Файл | Назначение |
| --- | --- |
| `setup_isaac.bash` | Подключение ROS 2 Jazzy, workspace и существующего профиля Fast DDS |
| `build.sh` | Сборка конфигурации симуляции |
| `install_dependencies.sh` | Установка зависимостей Jazzy |
| `run_isaac.sh` | Запуск MoveIt, ros2_control и RViz |
| `run_sim.sh` | Переадресация на запуск Isaac |
| `log_run.py` | Журналирование запуска и снимков конфигурации |

### Модель и управление

Для планирования подключена модель `ur_description` типа `ur10`, соответствующая
шести именам суставов, полученным из симуляции. Созданы SRDF, ограничения суставов,
конфигурации кинематики и контроллера.

Группа планирования — `ur_manipulator`. Контроллер — `ur10_controller`.
Action исполнения — `/ur10_controller/follow_joint_trajectory`.
Связь с JointState-топиками обеспечивает стандартный плагин
`joint_state_topic_hardware_interface/JointStateTopicSystem`.

Повторный издатель `/joint_states` из mock hardware или `joint_state_broadcaster`
не запускается. Источником состояний остаётся Isaac.

### Согласование времени и сети

В исходной сцене отсутствовал `/clock`, а состояния суставов имели относительные
штампы времени симуляции. Для работы MoveIt добавлен `joint_state_clock.py`:
он переиздаёт только полученные сообщения с текущим временем WSL в
`/ur10/joint_states`. Используется `use_sim_time=false`.

Существующий профиль `$HOME/.ros/fastdds.xml`, режим WSL NAT и `ROS_DOMAIN_ID=0`
сохранены. Связь проверена фактическим обменом командами и состояниями.
Настройки Windows Firewall и системный режим сети не изменялись.

### Диагностика и отключение лишних топиков

Проверка endpoints, включая запуск без ros2 daemon, показала следующий источник:

| Топик | Endpoint | Узел |
| --- | --- | --- |
| `/goal_pose` | Издатель | `isaac_ros_interface` |
| `/joint_commands` | Подписчик | `isaac_ros_interface` |

Оба endpoint создавались старым Windows-расширением `IsaacMoveitExtension`.
Изменён файл:

```text
C:\Users\user\Documents\Kit\shared\exts\IsaacMoveitExtension\Isaac_MoveIt_Extension_python\scenario.py
```

Создание старого интерфейса отключено по умолчанию. Его можно восстановить
переменной `ISAAC_ENABLE_LEGACY_MOVEIT_INTERFACE=1`. Сохранена резервная копия
`scenario.py.bak_welding_20261105`. При горячей перезагрузке ранее оставшийся узел
был уничтожен, отсутствие лишних топиков проверено повторно.

Это изменение находится вне Git-проекта и требует повторного применения
при переустановке расширения. Основной OmniGraph `/joint_states` → `/joint_command`
сохранён.

При последующей проверке в сцене появился отдельный издатель `/clock`
`_Graph_ROS_Clock_PublishClock`. Он относится к графу симулятора, а не к удалённому
старому интерфейсу. Служебные топики MoveIt/TF/контроллера при их запуске ожидаемы.

### Тестовый объект

Создан отдельный запуск `run_isaac_with_object.sh`. Узел `add_workpiece.py`
дожидается сервиса MoveIt и добавляет объект `welding_workpiece`:

| Параметр | Значение |
| --- | --- |
| Размеры | 0,30 × 0,30 × 0,20 м |
| Центр в `world` | (−1,0; 0,0; 0,1) м |
| Диапазон X | [−1,15; −0,85] м |
| Диапазон Y | [−0,15; 0,15] м |
| Диапазон Z | [0,0; 0,20] м |

Наличие, размеры и положение объекта подтверждены запросом `/get_planning_scene`.
Объект отображается в RViz и участвует в проверке коллизий MoveIt.

Проверены сборка, загрузка модели в RViz через WSLg и активация контроллера.
Через `/plan_kinematic_path` построены траектории поворота `wrist_3_joint`

## Ограничения и состояние этапа

Интеграция обеспечивает планирование и управление UR10 в Isaac. Совпадение
кинематики JAKA ZU12 и UR10 не предполагается; перенос на физический JAKA не проверен.

Управление работает по настенным часам, поэтому Play должен оставаться включённым
во время исполнения. При изменении адреса Windows-шлюза WSL потребуется актуализировать
пир в Fast DDS-профиле.

USD-заготовка в Isaac не создаётся автоматически. Полное совпадение геометрии
USD-робота с моделью планирования отдельным измерением не подтверждалось.

При завершении `move_group` по Ctrl+C воспроизводится segfault MoveIt 2.12.4
в деструкторах `TrajectoryExecutionManager`/`rclcpp::CallbackGroup`.
Обновление трёх пакетов его не устранило. Отдельно устранена повторная доставка SIGINT
из `log_run.py`. Сбой завершения остаётся открытым вопросом.

Эксплуатационные команды и подробности: [ISAAC_SIM.md](../ISAAC_SIM.md).
