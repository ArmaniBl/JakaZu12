# Формы заготовки и физический JAKA ZU12

Модуль использует геометрию объекта в сцене MoveIt. Поддержаны:

| Геометрия | Зоны прохода |
| --- | --- |
| BOX | Шесть контуров граней, двенадцать рёбер |
| CYLINDER | Окружности торцов `z_plus`/`z_minus`; рёбра `rim:z_plus`/`rim:z_minus` |
| Triangle mesh | Контуры плоских граней `face_0`, `face_1`, … и прямые рёбра `edge_<i>_<j>` |

Соседние треугольники с одинаковой нормалью объединяются в плоскую грань.
Диагонали триангуляции не становятся сварочными рёбрами. Поддержаны треугольные
и многоугольные, в том числе вогнутые, грани. Обход сохраняет вершины.
Имена mesh-граней относятся к конкретной сетке: после её перестроения выберите зону заново.
Нормали определяются согласованным порядком вершин треугольников и должны смотреть наружу.
Повторяющиеся вершины объединяются с округлением координат до 8 знаков после запятой.

Ограничения: один примитив или один mesh на объект, до 20 000 треугольников,
границы без отверстий и неоднозначных стыков. Самопересечения сетки и правильность
направления всех нормалей автоматически не аттестуются. Криволинейная боковая
поверхность цилиндра, сферы, конусы и извлечение швов из облака точек пока не поддержаны.
На окружности цилиндра ориентация постоянна, отступ и подвод направлены по нормали торца.

## Добавление объекта

После запуска сцены MoveIt выполните из корня workspace в WSL:

```bash
source setup_isaac.bash

# BOX: размеры X Y Z, метры.
ros2 run ur10_isaac_moveit_config add_workpiece.py \
  --shape box --dimensions 0.3 0.3 0.2 --center -1 0 0.1

# Цилиндр: высота и радиус; ось — локальная Z.
ros2 run ur10_isaac_moveit_config add_workpiece.py \
  --shape cylinder --dimensions 0.2 0.15 --center -1 0 0.1

```

Команды заменяют `welding_workpiece` только в MoveIt, USD-сцена Isaac не меняется.
Для другого имени используйте `--id`, для поворота — `--quaternion x y z w`.
Mesh JSON содержит массивы `vertices: [[x,y,z],…]` в метрах и `triangles: [[i,j,k],…]`.
Система объекта должна совпадать с системой планирования (`world` по умолчанию).
На физическом роботе указывайте измеренное положение реальной детали относительно
базы/`world`: координаты демонстрационного куба не являются калибровкой.

```bash
./weld.sh --list
./weld.sh --face z_plus --mode plan
./weld.sh --edge rim:z_plus --begin 0.1 --end 0.6 --mode plan
./weld.sh --face face_0 --mode plan
```

Выберите ID, существующий у текущего объекта. Веб-панель автоматически обновляет
доступные грани и рёбра.

В панели доступны три CAD-заготовки: тавр с косынкой, труба на пластине и пластина с волнистым швом. Смена детали обновляет сцену MoveIt/RViz. Во время планирования или выполнения замена блокируется. Поддержка BOX и CYLINDER сохранена для явного запуска через CLI.

## Профили и запуск JAKA под Jazzy

| Параметр | `isaac_ur10` (по умолчанию) | `jaka_real` |
| --- | --- | --- |
| Группа MoveIt | `ur_manipulator` | `jaka_zu12` |
| Конечное звено | `welding_tcp` | `welding_tcp` |
| Суставы | `shoulder_pan_joint` … `wrist_3_joint` | `joint_1` … `joint_6` |
| Обратная связь | `/ur10/joint_states` | `/joint_states` |
| Action драйвера | `/ur10_controller/follow_joint_trajectory` | `/jaka_zu12_controller/follow_joint_trajectory` |
| Возврат | Сохранённая конфигурация UR10 | Поза начала операции |

Имена сохраняются во всех сообщениях и ограничениях. Планировщик использует
собственные URDF, SRDF и кинематику JAKA. Неполная обратная связь, повторяющиеся
или чужие имена суставов отклоняются. Для реального исполнения проверяется
издатель `moveit_server`, присутствие Isaac не требуется. Проверки коллизий,
полноты декартова пути и стартовых положений сохраняются.

```bash
./build.sh --real

# Отдельный терминал: драйвер, MoveIt и RViz.
./run_real.sh <IP_КОНТРОЛЛЕРА>

# Другой терминал: добавьте измеренную заготовку указанным выше скриптом.
# Затем проверьте список зон и план без движения.
./weld.sh --robot jaka_real --list
./weld.sh --robot jaka_real --face face_0 --mode plan

# Веб-панель физического робота.
./run_web.sh --port 8090 --robot jaka_real
```

Исполнение запускается кнопкой панели или CLI с `--mode execute`.
По умолчанию CLI делает только preview. Панель подключается к отдельно запущенному
драйверу; кнопка запуска Isaac отключена. Для смены робота перезапустите панель.
Не запускайте Isaac и JAKA с общими именами сервисов в одном ROS-домене.

`run_real.sh`, `check_connection.sh`, `recover_robot.sh` используют Jazzy вместо Humble.
`build.sh --real` собирает четыре пакета; обычный `build.sh` сохраняет сборку только UR10.
Автоматическое включение JAKA отключено (`auto_enable=false`). Дополнительные
launch-параметры передаются после IP и частоты фильтра:
`./run_real.sh <IP> 0.5 payload_mass_kg:=0.4`.

Насадка включена в обе модели по умолчанию. `Link_6` — фланец JAKA; `welding_tcp` — TCP из CAD насадки. Физическая калибровка TCP не выполнялась. Для инструмента добавьте его
фиксированное звено и collision-геометрию в URDF, настройте массу/центр масс в
драйвере и укажите соответствующий `tip`. При запуске драйвер задаёт внешнюю нагрузку **3,0 кг** с центром масс в системе
фланца **X=0, Y=0, Z=+200 мм**. Это заданная оператором оценка. Измеренные значения
передаются через `payload_mass_kg` и `payload_centroid_{x,y,z}_mm`.
Параметр `configure_payload:=false` сохраняет нагрузку, уже записанную в контроллер.

### Зазор над столом и журнал фактического движения JAKA

При выборе ориентации для реального JAKA планировщик проверяет минимальный
вертикальный зазор между движущимися звеньями, горелкой и плоскостью столешницы.
Зазор в 10 мм проверяется по всем этапам с промежуточными выборками до 0,025 рад.
Если ориентация не проходит, поиск продолжается. Для выбранного маршрута
сохраняются звено, этап и зазор, а после перепланирования перед отправкой этапа
проверка повторяется. Остальные объекты по-прежнему проверяет MoveIt.

Во время выполнения компонент диагностики читает поток состояния JAKA с
TCP-порта 10000. В разделе `jaka_feedback` отчёта записываются команды и
фактические углы из одного пакета в единицах контроллера, ошибки и состояние
защиты, результат этапа и подтверждение отмены. При недоступном потоке причина
записывается в отчёт. Для записи не требуется менять параметры контроллера.

## Свои имена и возврат

Пример профиля: `src/ur10_isaac_moveit_config/config/jaka_welding_profile.json`.
Его поля переопределяют встроенный профиль:

```bash
./weld.sh --robot jaka_real --robot-config /путь/robot.json --mode plan
./run_web.sh --robot jaka_real --robot-config /путь/robot.json --port 8090
```

При смене `tip` задайте цепочку `frames`, заканчивающуюся этим звеном: она используется
для изображения робота. Имена должны совпадать с моделью, издателем состояний
и драйвером. Профиль сам не меняет URDF или настройки драйвера.

Для фиксированной конфигурации JAKA передайте `--return-pose /путь/return.json`
в CLI или при запуске панели. Формат: `{"units":"rad","joint_positions":{...}}`,
с полным набором шести имён профиля и углами в радианах.
Без файла JAKA возвращается в конфигурацию, считанную в начале планирования
текущей операции. Для `execute` это начало того же задания, а не состояние
предыдущего нажатия «Построить план». Возврат планируется до первого движения,
после исполнения проверяются углы. При ошибке/отмене автоматический возврат не запускается.

## Проверки

9 ноября 2026 года: собраны четыре пакета Jazzy, прошли 48 автоматических тестов
и браузерные проверки. Через настоящий MoveIt с моделью JAKA в изолированном
домене 122 построены полные маршруты по торцу малого цилиндра и треугольному mesh,
включая возврат к исходным `joint_1`…`joint_6`. Использовалась искусственная
обратная связь; SDK-драйвер и action-сервер движения не запускались.
Это проверка планирования, а не испытание физического робота.
Артефакты: `diagnostics/multishape_jaka_validation/`.
Дополнительно проверена цепочка веб-API → ApplyPlanningScene → чтение объекта
из MoveIt: цилиндр, призма и BOX заменяют один и тот же ID без дубликатов.
Браузерная проверка подтвердила автоматическую замену при выборе формы и обновление
списка граней на мобильном экране. Артефакты: `diagnostics/web_workpiece_validation/`.

## Physical JAKA completion

For `jaka_real`, successful welding now finishes with a straight 0.25 m lift
along world +Z from the last welding TCP position, retaining its orientation
and X/Y position during the lift. No final orientation change is requested.
The final normal retract and saved-pose return are replaced by this lift.
Intermediate seam retracts are unchanged. The complete lift is
planned with collision checking before execution begins; an unreachable or
blocked lift rejects the job. No lift is triggered after failure/cancellation.
Isaac retains its saved-pose return behavior. A supplied return-pose file does
not override the physical JAKA lift.
