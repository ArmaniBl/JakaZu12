# Имитация сварки по контуру грани

Поддержка BOX, цилиндров, mesh и профиля физического JAKA описана в
[SHAPES_AND_REAL_ROBOT.md](SHAPES_AND_REAL_ROBOT.md). Ниже — исходный сценарий BOX/Isaac UR10.

Модуль `welding_sim` читает объект из **сцены MoveIt** и определяет его шесть граней,
двенадцать рёбер и контуры граней. Первая поддержанная геометрия — один `BOX`.
Размеры, положение и поворот берутся из объекта, включая композицию позы объекта
и позы примитива. Координаты путей выдаются в `world`.
Это работа с известной геометрией, без распознавания камеры/облака точек.

Основной режим — **непрерывный контур выбранной грани**, а не четыре отдельных
подвода к её рёбрам. End-effector сохраняет ориентацию, проходит четыре стороны
прямоугольника и возвращается к начальной точке. Углы явно включены в путь,
диагонального срезания прямоугольника в геометрической генерации нет.

## Первый запуск на кубе

В Isaac включите Play. В первом WSL-терминале:

```bash
cd ~/jaka_zu12_welding
./build.sh
./run_isaac_with_object.sh
```

Во втором терминале:

```bash
cd ~/jaka_zu12_welding
# Показать обнаруженные рёбра, длины и координаты концов:
./weld.sh --list

# Предварительный просмотр верхней грани без движения (Ctrl+C для выхода):
./weld.sh --face z_plus

# Построить подвод, полный контур и отвод; показать план в RViz без исполнения:
./weld.sh --face z_plus --mode plan

# Построить и выполнить проход в Isaac:
./weld.sh --face z_plus --mode execute
```

Без `--face`/`--edge` выбирается верхняя грань `z_plus`.
По умолчанию `--mode preview`: команды движения не отправляются.
Режим `execute` сначала проверяет весь маршрут и требует присутствия издателя
состояний Isaac OmniGraph. При неполной декартовой траектории исполнение отклоняется.

В RViz добавлен дисплей **Welding seams** для `/welding/markers`:

- серый — рёбра объекта;
- зелёный — граница выбранной грани;
- красный — выбранный участок контура на поверхности;
- голубой — путь `tool0` с отступом от поверхности.

Предпросмотр держите запущенным для подключения RViz позднее.
`--once` публикует маркеры и завершает процесс; для автоматических проверок или уже открытого RViz.

## Выбор грани и части контура

Имена относятся к **локальным осям объекта**, поэтому сохраняют смысл при его повороте.

| Параметр | Грань куба из примера |
| --- | --- |
| `--face z_plus` | Верхняя, Z=0.20 |
| `--face z_minus` | Нижняя, Z=0 |
| `--face x_plus` | Ближняя к базе, X=-0.85 |
| `--face x_minus` | Дальняя, X=-1.15 |
| `--face y_plus` | Боковая, Y=0.15 |
| `--face y_minus` | Боковая, Y=-0.15 |

Выбор участка, например от 20% до 80% **всего периметра**:

```bash
./weld.sh --face z_plus --begin 0.2 --end 0.8
```

Для верхней грани периметр равен 1.2 м, выбранный участок имеет длину 0.72 м.
Начало обхода — ближайший к началу `world` угол, при равенстве выбирается
лексикографически первый. Обход положительный относительно внешней нормали грани.
При диапазоне `[0,1]` путь замкнут; при выборе части контура путь открыт.

Альтернативный режим одного ребра сохранён:

```bash
./weld.sh --edge x_plus__z_plus --begin 0.2 --end 0.8
```

`--edge` можно повторить; для каждого ребра строятся свой подвод и отвод.
`--face` и `--edge` одновременно не задаются.

## Параметры движения

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `--offset` | 0.03 м | Отступ `tool0` от поверхности по внешней нормали грани |
| `--clearance` | 0.05 м | Дополнительный отступ для подвода/отвода |
| `--step` | 0.005 м | Шаг дискретизации/декартового планирования |
| `--speed` | 0.02 м/с | Ограничение скорости рабочего прохода |
| `--scaling` | 0.05 | Коэффициент предельных скоростей и ускорений суставов |
| `--roll` | 0° | Поворот инструмента вокруг его оси Z |
| `--object` | `welding_workpiece` | ID объекта сцены MoveIt |

Ось +Z инструмента направлена к поверхности. Ориентация вдоль всего контура постоянна.
В режиме ребра отступ направлен по внешней биссектрисе двух смежных граней.
Скорость дополнительно проверяется по FK соседних точек готовой траектории;
при необходимости растягивается время и согласованно уменьшаются скорости/ускорения.
Это предел по дискретным отсчётам плановой траектории, не гарантия точности физического слежения.

Сначала планируется весь маршрут с проверкой коллизий. Проверяются несколько ветвей IK:
достижимость начального положения сама по себе не означает достижимость всего контура.
После подвода рабочий проход пересчитывается из фактической обратной связи суставов.
Порог проверки начальной позы MoveIt не увеличивается. Если повторное планирование
неполное, робот остаётся в точке подвода, проход не начинается.
Ctrl+C при исполнении запрашивает отмену активного action.

После успешного последнего прохода и отвода выполняется дополнительный этап
`workpiece:return` — возврат в фиксированную конфигурацию из
[`config/return_pose.json`](../src/ur10_isaac_moveit_config/config/return_pose.json).
Сохранены фактические углы Isaac: `0, -2.0944, -1.0472, -1.5708, 1.5708, 0` рад
для shoulder_pan, shoulder_lift, elbow, wrist_1, wrist_2, wrist_3 соответственно.
Возврат планируется вместе с остальными этапами до отправки первого движения.
Для исполнения он перепланируется от стабильной обратной связи, без повторного
решения IK для целевой позы: используются сохранённые углы всех шести суставов.
Контроллер удерживает достигнутую конфигурацию. В отчёте сохраняются `return_pose`,
`return_pose_actual` и `return_pose_errors_rad`.

У куба по X=-1 дальние углы близки к пределу досягаемости UR10.
Для верхнего контура проверено полное планирование с отступом 0.03 м.
Отступ 0.10 м в некоторых конфигурациях даёт только часть пути и отклоняется.
Не все шесть граней обязательно доступны роботу; нижний контур также требует
учёта реальной опоры, если она будет добавлена в сцену.

Горелка и TCP ещё не моделируются: `tool0` изображает инструмент и идёт на расстоянии
от объекта, без контакта, сварочной дуги, нагрева и формирования шва.
Сам объект по-прежнему создаётся в MoveIt/RViz, а не в USD-сцене Isaac.

## Отчёты и проверки

Каждый запуск сохраняет выбранную геометрию, позы прохода, параметры, длительности,
долю декартового пути и результат в `diagnostics/welding/*.json`.
Успешное планирование отмечается `planned`, исполнение — `executed`, ошибка — `failed`.
В `preview` отчёт записывается после выхода через Ctrl+C или сразу при `--once`.

Проверки геометрии, преобразования поз, участков контура, отказа на частичном пути
и ограничения скорости:

```bash
source setup_isaac.bash
python3 -m unittest discover -s src/ur10_isaac_moveit_config/test -v
```

Проверка 5 ноября 2026 года: восемь тестов прошли, полный верхний контур
`z_plus` на кубе `0.30 × 0.30 × 0.20 м` в `(-1,0,0.1)` выполнен через Isaac.
Параметры проверки: `--offset 0.03 --scaling 0.15`, скорость прохода 0.02 м/с.
Доля декартового пути 1.0, подвод и проход с отводом завершились успешно.
Отчёт: `diagnostics/welding/20261105_203647_187215.json`.
После отвода `world → tool0`, рассчитанное по обратной связи суставов, составило
примерно `(-0.84998, -0.15002, 0.28002)` м при задании `(-0.85, -0.15, 0.28)`.
Это проверка одного контура и конечного положения, не аттестация точности слежения
по всем точкам и не проверка всех граней.
