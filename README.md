Ветка `welding` настроена для **Isaac Sim на Windows 11 + ROS 2 Jazzy в WSL2 Ubuntu 24.04**.
Для симуляции используется отдельная модель UR10, группа MoveIt `ur_manipulator`.
Инструкция и результаты проверки: [docs/ISAAC_SIM.md](docs/ISAAC_SIM.md).

```bash
cd ~/jaka_zu12_welding
./build.sh
./run_isaac.sh
```

Запуск с заготовкой `30 × 30 × 20 см` в `world: (-1, 0, 0.1)`:
`./run_isaac_with_object.sh` (объект в MoveIt/RViz, с проверкой коллизий).

Имитация сварки по выбранной грани: `./weld.sh --face z_plus` — предпросмотр,
`./weld.sh --face z_plus --mode plan` — планирование,
`./weld.sh --face z_plus --mode execute` — выполнение в Isaac.
Выбор участка и параметры: [docs/WELDING.md](docs/WELDING.md).

`./run_sim.sh` запускает ту же конфигурацию Isaac. Сначала включите Play в Isaac Sim.
Добавлены цилиндры, mesh-объекты и режим физического JAKA под Jazzy:
[инструкция](docs/SHAPES_AND_REAL_ROBOT.md).
Сборка физического режима: `./build.sh --real`; панель: `./run_web.sh --robot jaka_real`.
Ниже сохранена историческая документация JAKA/Humble; для текущей ветки используйте
инструкцию выше. Обычный `build.sh` собирает только пакет симуляции UR10.

Готовый workspace для JAKA ZU12 через ROS 2 Humble, MoveIt 2 и RViz.
Включает драйвер JAKA SDK, URDF, меши, симуляцию, запуск физического робота,
коллизии окружения (пол, две гусеницы, блок питания) и сохранение журналов.

## Требования

- Ubuntu 22.04 x86-64 (обычная установка или WSL2).
- ROS 2 Humble.
- Графический сервер для RViz. В WSL требуется работающий WSLg или VcXsrv.
- Контроллер JAKA с совместимой прошивкой и сетью.

## Установка на новом устройстве

Клонируйте репозиторий и соберите workspace:

```bash
git clone https://github.com/ArmaniBl/JakaZu12.git
cd JakaZu12
chmod +x *.sh
./install_dependencies.sh
./build.sh
source install/setup.bash
```

В новом терминале перед командами ROS выполняйте:

```bash
source /opt/ros/humble/setup.bash
source /путь/к/JakaZu12/install/setup.bash
```

## Проверка без робота

```bash
./run_sim.sh
```

Должны открыться RViz и виртуальная модель ZU12.

Группа планирования: `jaka_zu12`. Скрипты запуска сами подключают окружение ROS
и workspace. Для симуляции подключение к настоящему роботу не требуется.

## Настройка окружения

Положение и размеры объектов меняются в
`src/jaka_zu12_moveit_config/scripts/add_environment.py`. Координаты заданы
в метрах относительно `world`: X вперёд, Y влево, Z вверх. Пол имеет размеры
`6 x 6 x 0.10 м`, его верхняя поверхность находится на `Z = 0`.
Центры гусениц по X: `0.65` и `-0.47 м`, блока питания: `0.10 м`.
После изменения перезапустите launch, чтобы обновить сцену.

## Журналы диагностики

`run_real.sh`, `run_sim.sh` и `recover_robot.sh` автоматически сохраняют каждый
запуск в отдельную папку `diagnostics/`. Путь выводится в терминале при запуске.
В ней находятся `console.log` с общим выводом и временем получения сообщений,
`ros/` с журналами ROS, `session.json` с командой запуска и кодом завершения,
а также `snapshot/` с конфигурацией и исходником драйвера на момент запуска.
Время сообщений записывается в UTC. При `Ctrl+C` сигнал передаётся ROS,
после завершения сохраняется итоговый статус.

Для диагностики передавайте всю папку соответствующего запуска. Журналы
содержат IP контроллера и локальные пути. Запись не опрашивает контроллер
дополнительно и не является записью фактических положений суставов в rosbag.
Старые журналы автоматически не удаляются.

## Подключение физического робота

1. Подключитесь к Wi-Fi контроллера.
2. Остановите сохранённую программу в JAKA App.
3. Отключите автозапуск программы и проверьте DI `Start Program`.
4. Проверьте сеть:

```bash
./check_connection.sh 10.5.5.100
```

5. Освободите рабочую зону и подготовьте аварийную кнопку.
6. Если JAKA App и веб-интерфейс недоступны, остановите программу и восстановите
   контроллер через SDK (команда потребует ввести `RECOVER`):

```bash
./recover_robot.sh 10.5.5.100
```

7. Запустите:

```bash
./run_real.sh 10.5.5.100
```

При запуске MoveIt автоматически добавит настроенные препятствия окружения.
Для ZU12 также явно задаётся отсутствие внешней нагрузки: масса `0 кг`, центр
масс `(0, 0, 0) мм`. При установке инструмента перед движением укажите его
реальную массу через `payload_mass_kg` и настройте фактический центр масс.

`auto_enable` по умолчанию выключен. После запуска вручную включите и активируйте
робот через JAKA App, убедившись, что сохранённая программа не запускается.

В RViz установите `Velocity Scaling` и `Acceleration Scaling` в `0.05`. Сначала
нажимайте `Plan`, проверяйте траекторию и только затем `Execute`.

## Диагностика

```bash
ros2 node list
ros2 topic hz /joint_states
ros2 action list -t | grep jaka_zu12
```

Ожидаемый action:

```text
/jaka_zu12_controller/follow_joint_trajectory
```

Другие имена можно передать без правки исходников:

```bash
ros2 launch jaka_zu12_moveit_config real_robot.launch.py \
  ip:=10.5.5.100 \
  joint_states_topic:=/robot/joint_states \
  trajectory_action:=/robot_controller/follow_joint_trajectory
```

Не запускайте `jaka_driver` одновременно с `jaka_planner`. При неожиданном
движении используйте физический аварийный останов: `Ctrl+C` не является
аварийной остановкой.

Если робот остановился до конечной точки, сначала прочитайте сообщение в JAKA
App. После protective stop или ошибки остановите запуск через `Ctrl+C`, выполните
ручное восстановление и повторное включение в JAKA App, а затем снова запустите
`./run_real.sh 10.5.5.100`. Драйвер не сбрасывает защиту автоматически.

## Состав и ограничения

В репозитории три пакета: `jaka_description`, `jaka_planner` и
`jaka_zu12_moveit_config`. Каталоги `build`, `install`, `log`, `diagnostics`
генерируются локально и исключены из Git. Gazebo, базы траекторий и конфигурации
других роботов не включены.

Масса нагрузки по умолчанию равна нулю: это настройка для пустого фланца.
Фильтр servo-команд по умолчанию `0.5 Гц`. Суставы модели имеют ограниченный
тип `revolute`; пределы второго, третьего и четвёртого суставов сохранены из
URDF. Драйвер отклоняет траектории с углами вне `-360...360 градусов` и
расхождением начальной позы более `2 градусов`.

Сборка и проверка launch-файлов выполнялись на Ubuntu 22.04 с ROS 2 Humble.
Это не заменяет проверку движения на конкретной установке.
Модель и SDK заимствованы из исходного проекта JAKA ROS2; для этих компонентов
действуют условия их правообладателей.
